# Weavefield · 产品需求文档（PRD）

> 版本：0.1 · 状态：立项草案 · 日期：2026-10-20 · 产品名：织域 / Weavefield

## 1. 产品一句话

为 2–8 人产品与开发小团队提供实时协作的项目空间：**需求文档、流程图、开发任务指向同一组业务对象**，减少内容复制、状态漂移与上下文切换；后续让 AI 以「提案 + 审批」方式参与协作。

## 2. 背景与设计机会

常见工作流是文档写在一处、流程图画在另一处、任务放在第三处。需求改变后，设计图节点和任务描述往往没有同步，成员也难追溯某项工作的上下文。

Weavefield 的假设：相比再做一个万能笔记软件，用户更在意 **一个需求在不同视图中的稳定关联与可追踪状态**。此假设尚需真实用户验证，不是市场结论。

## 3. 目标用户与典型场景

- 核心：小型 Web / App 开发团队、学生课程项目组、独立开发者与 1–3 名协作者。
- 次级：产品设计与研发混合的小团队，常常同时维护 PRD、流程图、开发任务。
- 暂不面向：大型企业复杂审批体系、高频财务表格、大规模数百人联合编辑。

**黄金场景：** 三人一起开发一个 App。A 在 BlockNote 编辑「邮箱注册」需求，B 在同一文档补充验收标准，C 在流程图上编辑节点「验证邮箱」并创建关联任务。点击任意一端可跳到其余两端。

## 4. 价值主张

1. 文档协作可靠：多人同时编辑、在线光标、断线重连、刷新恢复。
2. 工作对象有统一身份：稳定的 requirement ID、node ID、task ID 与关联关系。
3. 用户掌握变更：历史可追溯；AI 修改先预览，再确认。
4. 体验精致：无障碍、空状态、快捷操作、清晰同步状态、稳定响应。

| P0 | 多人富文本 | BlockNote + Yjs + Hocuspocus，协同光标 | M1–M2 |

| P1 | 开发任务 | 待办/进行中/完成、负责人、截止时间 | M3 |
| P1 | 跨视图关联 | 文档块 / 需求 ↔ 流程节点 ↔ 任务；双向跳转 | M3 |

## 6. MVP 核心用户故事

### US-01 工作空间

作为 owner，我可以创建工作空间并邀请一名 editor，以便两个账号访问同一组文档。

**验收**：非成员不能读取空间或订阅文档；viewer 能看到内容但修改请求会被服务端拒绝。

### US-02 可靠协同

作为协作者，我在两台浏览器同时编辑同一份文档，双方无需手动刷新即可收到修改；能看见其他人的在线光标。

**验收**：50 次交错输入/删除不丢失最后的内容；刷新后收敛到一致状态；断线重连不出现重复段落。

### US-03 权威持久化

作为用户，服务重启后我仍能看到上次已经确认保存的文档内容。

**验收**：Yjs 更新写入二进制存储，重启后能够恢复；空文档与不存在文档处理明确。

### US-04 三视图关联

作为团队成员，我能在文档的一个需求块上创建流程节点和任务的关联，随后从任一视图跳转到其余视图。

**验收**：关系记录引用实体稳定 ID；移动节点不破坏关系；删除实体后有明确的失效/清理策略。

### US-05 AI 协作（非首版）

作为 editor，我可以请 AI 检查「需求与任务是否一致」。AI 展示引用来源、拟议变更及理由。我确认后才实际修改，且可撤销。

**验收**：AI 没有直接写入权限；未经批准不能更改共享文档；多用户并发情况下能检测版本冲突。

## 7. 非功能要求与工程门槛

- 安全：所有 REST 与 WebSocket 的读写都在服务端鉴权；最小权限；WSS；速率限制与日志脱敏。
- 可靠性：Yjs 二进制快照，确保原子写入；生产环境需数据库事务或稳定存储。
- 性能（阶段目标）：在测试环境下，两人 100 KB 文档正常键入，单次更新本地网络可视延迟目标 < 250 ms；以实测为准。
- 可访问性：键盘操作、对比度、焦点可见、ARIA 标签。
- 测试：单元 + API 集成 + 两浏览器 Playwright E2E + 断网重连 + 权限越界 + 重启恢复。
- 可迁移性：导出格式清晰；不得锁死在仅能通过 UI 读取的私有状态里。

## 8. 评估指标（内部验证）

- 核心闭环完成率：首次创建空间后完成 2 人协作 ≥ 70%（小样本目标，不是市场数据）。
- 文档收敛正确率：E2E 两用户并发测试通过率 100%。
- 恢复可靠性：重启后保存内容一致；权限测试零越权。
- 可理解性：首次使用者能解释文档、流程图和任务的关系。

## 9. 产品风险

- 范围膨胀：先做好文档协同，再做流程与任务，不三端一起上线。
- CRDT 持久化错误：不能随意把 JSON 恢复成新 Y.Doc 充当历史。
- 安全感假象：开发阶段的固定 token 不能用于生产环境。
- AI 幻觉：AI 只能提出带可审查来源的建议，不能直接改共享状态。
- 市场竞争：不宣称取代 Notion/Figma，突出小团队的跨视图需求追踪。

## 10. 第一版交付定义

M1+M2 达标后发布 `v0.1`：完整的**注册/邀请 → 协同文档 → 在线光标 → 刷新重连 → 二进制保存/恢复 → 服务端权限**闭环，并有 Playwright 演示与架构说明。流程图和 AI 是下一步，而非 v0.1 的硬条件。
