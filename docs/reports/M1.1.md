## 风险、限制与未验证项

- 安全：数据库账号只服务于隔离本机容器；未连接生产库。Docker 官方镜像初始化账号在容器内权限较高，生产部署仍需另行设计最小权限账号。本轮没有认证或租户授权入口，也没有新增任何权限绕过。
- 迁移：初始 Migration 适用于干净库。已有无迁移历史的数据不能直接套用；须先备份、比对并制定基线方案。已应用迁移不得随意修改。级联删除是物理删除，未来业务删除需先明确归档与授权策略。
- 持久化：本轮证明 PostgreSQL 命名卷重启后关系与 Bytes 数据保留；不是备份恢复、容灾或生产高可用验证，也未将 M0 的 Yjs 文件快照迁移到数据库。
- 兼容性：macOS arm64 Node + Docker Linux arm64 PostgreSQL 已实测。Windows 命令只做文档核对，未在 Windows 执行；新增 GitHub Actions 配置未推送，Linux amd64 CI 尚未执行。
- 性能：没有负载基准；构建仍有既有大 chunk、Zod PURE 注释提示，未在本轮作无关优化。Turborepo 远程缓存返回 403 后回退，强制执行的检查均通过；E2E 有 NO_COLOR/FORCE_COLOR 提示，不影响结果。
- 本轮没有未解决的本地功能失败。Docker 缺失、环境变量缺失均已解决；外部工具自身的更新提示不代表需要升级项目依赖。

## 技术学习总结

**Schema、Migration 与 Client。** Schema 是类型与关系的声明；Migration 是可审查、按历史顺序执行的 SQL，用 `_prisma_migrations` 记录应用状态；Client 是由 Schema 生成的类型安全查询代码。`generate` 不建表，`deploy` 不生成 Client。本轮在空库应用 SQL，再验证数据库与 Schema 无差异，并携带数据重复 deploy 验证幂等部署。

**数据库访问流程与 NestJS 边界。** 本轮验证流程是：脚本校验 DATABASE_TEST_URL → 设置当前进程 DATABASE_URL → 从数据库包导入共享 prisma → 连接 PostgreSQL → 事务/查询 → 显式断开。入口为 `packages/database/src/index.ts`，集成脚本为 `packages/database/test/integration.cjs`。CommonJS 编译与包导出已经实测；NestJS API 本轮尚未连接数据库。后续应通过 provider 注入同一实例，在模块启动和服务关闭时管理连接，不能把此预留方案描述为已完成的 NestJS 集成。

**事务。** 创建空间、用户与 owner 成员涉及多表写入，事务让它们整体成功或整体撤销，避免半成品关系。本轮通过显式抛错验证 User 与 Workspace 写入一同回滚；事务不等于授权检查，也不能取代 CRDT 合并。

**多租户关系。** Workspace 是业务资源的空间边界，Membership 将用户与多个空间及各自角色关联。复合主键保证一人一空间只有一条成员关系；按 userId 的索引便于反向查空间。Document.workspaceId 和外键保证归属对象存在，但不会自动判断请求者是否属于该空间，后续服务端仍须做授权。

**取舍。** 保留全部模型作为可重复数据库基线，避免删除后续设计；仅启用基础设施与验证，不提前实现业务 Repository 或权限系统。进程内单例减少重复连接池，后续各服务自行管理生命周期；没有引入 Redis、消息队列或新的业务依赖。
