注册请求由 AuthPanel 经 Vite `/api` 代理到 AuthController。Controller 检查 Origin、自定义头、JSON、输入及尝试次数；PasswordService 派生 scrypt 摘要；AuthService 在同一事务创建 User 和 Session，并轮换当前 Cookie 对应会话。响应只返回公开用户字段与到期时间，随机 Token 只进入 HttpOnly Cookie。

登录先用 emailCanonical 查用户并验证密码，再事务创建新 Session、撤销当前旧 Token。`me()` 将 Cookie Token 摘要后查询有效 Session，仅返回其关联用户；`logout()` 删除当前 Session 后清 Cookie。DatabaseService 复用数据库包实例，通过 onModuleInit/onModuleDestroy 连接与断开。

前端只依据真实 API 显示身份，刷新、聚焦、可见及每分钟重新验证，并设置到期计时器；请求序号防止旧响应覆盖新状态。退出响应丢失时重新查询服务器，避免保留已撤销的身份。网络不可用显示失败状态；不保存 Token 到 React 状态或 localStorage。

## 数据模型、迁移与设计取舍

- User 新增可空 emailCanonical（唯一）及 passwordHash，Session 为第 11 张表，userId 外键级联 User 删除。Session 保存唯一 tokenHash、createdAt、expiresAt、revokedAt，并为 userId、expiresAt 建索引；不代表租户或文档授权。
- 增量迁移先只读检查旧邮箱 trim/lowercase 后的冲突；冲突停止，不自动合并账号。随后事务执行 DDL 和回填，保留旧 email、ID、昵称、创建时间；旧用户没有默认密码。可空字段保证 M1.1 原有写入仍可运行，认证注册始终填充这两个字段。
- Migration 是数据库结构与数据升级的版本记录；`migrate deploy` 按历史应用，重复部署不重复执行。Prisma Client 是由 Schema 生成的查询代码，`generate` 不会替代迁移。Schema/Client/数据库一致性由真实迁移与 Drift 检查验证。
- scrypt 使用 N=32768、r=8、p=3、16 字节随机盐和 timingSafeEqual；选择 Node.js 原生异步实现，避免增加原生密码依赖。密码派生限制每进程并发为 2，仍有 CPU/内存成本。
- Session 使用 32 字节安全随机 Token，数据库只存 SHA-256 摘要。选择数据库 Session 便于立即退出和撤销；代价是身份查询依赖数据库。七天绝对过期，不滑动续期。
- Cookie 为 HttpOnly / SameSite=Lax / Path=/，无 Domain；生产强制 HTTPS WEB_ORIGIN、Secure 与 __Host- 前缀。写请求还要求精确 Origin、JSON、自定义头并拒绝 cross-site；JSON 最大 4 KiB。
- 单实例内存限流：注册每 IP 10 次、登录每 IP 20 次、每账号共 10 次 / 15 分钟，最多 10000 桶，不信任客户端 X-Forwarded-For。选型与限制见 [ADR-0004](../decisions/ADR-0004-database-cookie-sessions.md)。

## 遇到的问题及保留证据

- 首次红灯测试证明原 API 没有 register 路由（404）；实现后真实 API 测试通过。
- 旧邮箱冲突探针发现 Prisma 在显式事务失败后会隐藏原错误。将只读冲突预检移到 DDL 事务之前，重新验证明确拒绝，且没有添加字段或改变原记录；DDL 和回填仍在事务内。最终成功/冲突探针库分别为 `weavefield_test_upgrade_success_637747f3d2d7`、`weavefield_test_upgrade_conflict_84aa60499b88`，保留供审查。开发过程其他专用探针库也保留；冲突库的失败迁移记录属于预期负向证据。
- 首次完整 E2E 为 10 通过、2 失败：新增提示文字换成两行，两个宽度下页面高度均为 926px。同浏览器只替换文案测得段落由 43.1875px 降到 21.59375px，页面恢复 905px。最终缩短提示，保留 Nova/权限边界，侧栏定向 2/2 与完整 12/12 重跑通过；8px 容差、主面板宽度、标题、控件、溢出及精确协作断言保留。
- 未登录 `/api/auth/me` 按协议产生 401；布局控制台检查仅豁免该地址的预期 401，其他错误仍失败。
- 初次离线依赖解析受已有私有 Registry 元数据缺失影响；复用锁内 Express 版本补全直接依赖后，offline frozen-lockfile 安装通过。没有升级现有依赖。
- Vite 仍报告依赖注释及大于 500 KiB 的 chunk，Playwright 有 NO_COLOR/FORCE_COLOR 警告；未进行无关打包重构。Turbo 远程缓存不可用时使用本地执行，最终检查已强制禁用缓存复用。

日志、最终 E2E JSON/截图、早先失败 Trace 和完整 Diff 位于被忽略的 `.playwright/m12-validation/`，没有覆盖历史 M0/M1.1 验证记录。该目录还包含本地测试环境文件，不应整体上传；审查只需 `changes.patch` 与需要的日志。

## 风险、未验证项与下一步

- 本地验收通过不代表新 Linux CI 通过；本轮未提交或推送，因此新增 CI 步骤尚待远端验证。Windows 浏览器和真实 HTTPS 部署未验证；生产 Cookie 属性通过真实 HTTP 接口检查及配置单测，但未搭建 TLS 部署。

- 新 Session 外键会在用户删除时删除其全部会话，这是预期退出行为；没有增加删除用户 API。新增会话需数据库查询，尚无负载/压力测试。
- 本轮会话持久化验证包含连接及 API 生命周期重启；数据库容器重启持久化沿用 M1.1 已有结论，没有把历史测试写成本轮重跑。M0 二进制快照重启恢复已在本轮 E2E 再次验证。
