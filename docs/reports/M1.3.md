## 技术原理与执行流程

Workspace 与 User 通过 Membership 构成多对多关系；复合主键 `(workspaceId,userId)` 阻止重复成员，`userId` 索引支持当前账号的空间列表，Workspace.slug 唯一。现有结构已经满足本轮要求，不增加或修改 Migration。

请求先经 `auth/session.guard.ts`，严格解析 Cookie 并复用 AuthService.me 查询 Session 摘要、过期和撤销状态。写请求沿用精确 Origin、JSON、自定义头及 cross-site 拒绝。`workspaces.controller.ts` 做运行时字段白名单与类型校验，身份来自服务器，不接收 ownerId 或创建者 userId。`workspace-access.service.ts` 在事务内检查真实 Membership；Service 显式 select 空间或成员的安全 DTO，不读取返回密码、Token 或其他认证字段。

创建空间时，`WorkspacesService.create` 在同一事务中写 Workspace 与 OWNER Membership，避免只写出空间而没有初始管理员。列表直接按 Session 用户过滤；详情与成员读取使用 RepeatableRead，令权限检查与数据读取处于同一快照。非成员和不存在空间返回相同 404；已加入但管理越权为 403。

`WorkspacesService.write` 对同一 Workspace 行执行参数化 `FOR UPDATE`，获得锁后重新检查 OWNER，再执行名称或成员修改。`protectOwner` 在锁内判断目标及 OWNER 数量；仅剩一位时拒绝删除或降级（409）。采用 ReadCommitted，使锁等待后的查询看见前一个事务的提交。仅仅“在事务里计数后更新”仍有写偏差；行锁确保同空间写入串行化，跨空间可并行。设计及替代方案见 [ADR-0005](../decisions/ADR-0005-workspace-membership-rbac.md)。

React 的 `auth/AuthContext.tsx` 提取原 AuthPanel 的真实会话状态、刷新、到期及竞争保护；`AuthPanel` 和 `WorkspacePanel` 共用同一身份源。后者按 userId 隔离组件，localStorage 只存选择 ID，列表与详情每次由 API 验证。401 清理身份和受保护状态；失效选择与读取期间发生的移除清理本地 ID；403 显示错误并重新读取真实角色。窗口打开时手动、聚焦及每分钟刷新，响应序号和生命周期检查避免旧请求覆盖当前状态。

真实空间只在独立管理面板展示。Nova、M0 文档和 localhost 协作 Demo 不会因切换空间变成私有资源，也不因为登录或 Membership 而获得正式协作权限。复用现有视觉风格、原生 dialog 和表单，无新增 UI 框架。

## 开发中发现的问题与修复

- 先写真实 API 用例，缺少路由时得到 404，随后实现并通过；浏览器首次因缺少工作空间入口失败，后续实现后通过。初始红灯记录保留，不是最终未解决失败。
- Chromium 的 HTML pattern 使用 v 语法，未转义连字符产生 Console 错误；改为转义字符。选择框内选项影响精确 label 匹配，补上明确 aria-label，真实切换测试通过。
- 新增 E2E 数组的推断产生 `string | undefined`，首次 typecheck 失败；将固定数据声明为只读元组后重新检查通过，失败日志 `typecheck.log` 保留。
- 最终审查发现显式 `role: null` 被空值合并当成默认 VIEWER。先加用例确认错误 201（预期 400，`role-null-red.log`），仅在字段省略时默认 VIEWER；修复后 Workspace、typecheck、unit、build 和完整 E2E 再次通过。
- 初始 UI 切换超时的 Trace 与截图保留在 `ui-create/`，修复后单项及完整测试通过。没有跳过失败断言或降低精确匹配。

## 风险、限制与未验证项

- **Linux 兼容性：未验证。** CI 已增加 `pnpm test:workspaces`，保留 PostgreSQL 16、初始与增量迁移、旧数据升级、认证、单元、类型、构建及完整 E2E。此次本地结果不代表远端通过。
- **权限与持久化：** 最后 OWNER 保护覆盖 WorkspacesService 写入口；数据库无跨行“至少一位 OWNER”约束，直接 SQL 或未来 User 删除级联可绕过。当前没有 User / Workspace 删除 API，新增入口必须遵守相同锁协议。原有历史无 OWNER 草案空间不自动修复，避免擅自修改旧数据。
- **权限时效：** 服务端每个请求重新检查；合法读取事务可能在并发撤权后结束。前端无成员变更推送，窗口未刷新前可能显示旧角色，不能以 UI 当授权依据。
- **性能：** 同空间写入串行化，事务超时返回 503，不自动重试；未进行高并发压测或大成员列表分页。数据库连接复用现有 NestJS Provider 和每进程统一 Prisma Client，无新增池。
- **前端兼容：** 实际验证 macOS Chromium；Firefox、WebKit 和 Windows 尚未执行。保留桌面布局及原无障碍标签，新面板支持原生 dialog、键盘与移动端布局。
- **构建警告：** 仍有编辑器包超过 500 kB 的 Vite 警告；Turborepo 远程缓存返回 403 后退回本地强制执行；Playwright 有 NO_COLOR / FORCE_COLOR 冲突提示。均未导致最终检查失败，未为消除警告做无关改动。
- **阶段边界：** 无邮件邀请、公开账号搜索、物理空间删除、审计、M1.4 文档资源权限或 M2 正式协作鉴权。M1.2 的单实例登录限流及其他既有生产限制保持不变。未完成生产部署、压测或安全审计，不宣称 M1 整体完成。
