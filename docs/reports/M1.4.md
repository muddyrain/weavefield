## API 与权限

路径为 API 内部路径，Web 通过同源 `/api` 代理。所有接口复用 SessionGuard，写入复用 Origin、JSON 和 `X-Weavefield-Request: 1` 校验。

| 路由 | 成功状态 | OWNER | EDITOR | VIEWER | 非成员 |
|---|---|---|---|---|---|
| GET /workspaces/:workspaceId/documents | 200 | 允许 | 允许 | 允许 | 404 |
| POST /workspaces/:workspaceId/documents | 201 | 允许 | 允许 | 403 | 404 |
| GET /workspaces/:workspaceId/documents/:documentId | 200 | 允许 | 允许 | 允许 | 404 |
| PATCH /workspaces/:workspaceId/documents/:documentId | 200 | 允许 | 允许 | 403 | 404 |
| POST /workspaces/:workspaceId/documents/:documentId/archive | 200 | 允许 | 允许 | 403 | 404 |

未登录 / 过期 / 退出统一 401。不存在、跨空间或已归档的文档为 404，优先于角色不足判断。创建和重命名只接受 title，去首尾空白后 1–200 个 Unicode 字符，拒绝控制字符、非法 ID 和未知字段；归档接受 JSON 空对象。字段 / ID 格式错误为 400。输入沿用现有 4 KiB 上限。

DTO 仅含 id、workspaceId、title、createdAt、updatedAt、archivedAt，时间为 JSON ISO 字符串。没有 ownerId、密码哈希、Cookie、Session Token、数据库凭据或 ydocRoomName。房间由服务器生成，不是访问凭据。

## 核心原理与执行流程

源码入口：[Controller](../../apps/api/src/documents/documents.controller.ts)、[Service](../../apps/api/src/documents/documents.service.ts)、[前端面板](../../apps/web/src/components/DocumentsPanel.tsx)。

1. 列表与详情：Guard 验证真实会话 → Controller 校验路由参数 → RepeatableRead 事务内 WorkspaceAccess.require 校验成员 → 查询 workspaceId + archivedAt=null，详情再限制 documentId。列表按 updatedAt 降序、id 升序，返回 select 白名单。
2. 创建：ReadCommitted 事务锁 Workspace 父行 → 锁后重新读取成员与角色 → OWNER / EDITOR 创建元数据及 `doc:${randomUUID()}`。现有唯一约束拒绝冲突；仅对 room P2002 最多三次全新事务重试，耗尽返回 409，失败事务不留下新文档。
3. 重命名：同一锁协议 → 查询空间内未归档文档 → 验证写角色 → 条件 updateMany，只改 title，由 Prisma 更新 updatedAt → 再读取安全 DTO。没有更新 archivedAt=null 的入口。
4. 归档：同一锁协议和未归档条件 → 设置 archivedAt，检查影响行数 → 返回归档元数据。不 DELETE，不删除 DocumentSnapshot。后续详情、改名和归档均 404；并发改名不能重新启用。
5. React：WorkspacePanel 按用户 / 空间 / 角色挂载 DocumentsPanel，关闭或切换时卸载；alive + revision 丢弃旧请求。列表刷新清理旧详情，写成功后重新获取排序后的列表。401 清理身份，403 隐藏过期写入口并提示刷新角色，404 清理失效详情。没有持久化正文或向真实文档分配 M0 房间。

关键位置：Service 的 list/detail 在第 21 / 28 行，write 在第 34 行，create / rename / archive 在第 42 / 58 / 67 行；DocumentsPanel 的 reload / select / mutate 在第 34 / 51 / 64 行。

空间父行锁沿用成员管理协议，使成员降级与文档写入有一致顺序。代价是同空间元数据写入串行化；本阶段没有高频正文写入，不引入另一套锁或权限框架。读事务保证成员验证与数据在同一快照，已发出的合法读取可能在并发撤权后完成，后续请求重新鉴权。

### 验证中发现并处理的问题

1. 新 E2E 的辅助函数最初命名为 document，遮蔽 evaluate 回调中的 DOM 全局，typecheck 报 TS2339。改名为 createDocument，重新检查通过，未改应用逻辑。
2. 首轮完整 E2E 为 14 通过、2 失败、11 因 beforeAll 失败未运行。原认证测试消耗 7 次注册配额，文档夹具新增 4 次后超过每 IP 15 分钟 10 次注册限制，随后原 Workspace 夹具也收到 429。原 limiter 按设计工作，未修改认证业务、放宽限额或等待窗口。
3. 修复位于新文档 E2E 本身：在随机 loopback 端口启动独立的真实 NestJS 实例完成注册 / 登录，隔离夹具认证限流状态；共用受保护的随机测试数据库，正常下发 HttpOnly Cookie。浏览器文档操作仍走原 E2E API，由真实 SessionGuard 读取同一数据库验证。没有伪造 Cookie、直接写 Session、mock 文档成功响应或跳过旧测试。afterAll 关闭实例并清理本轮夹具。
4. encoding-guard 扫描返回退出码 2：把 WorkspacePanel 原有 JSX 中 `detail?.id ?? ''` 误认为中文丢失。已精确比对该行与 HEAD 相同；所有变更文件严格 UTF-8 解码且无 U+FFFD。保留误报，不为压掉扫描结果改写原代码。

## 风险、限制与下一步

- 安全：元数据授权由服务端强制；M0 仍为仅 localhost 的共享演示，不能公开部署。正式 Hocuspocus 权限、短期文档票据和 reader 写保护属于 M2。
- 数据：归档不可从当前 UI 恢复，没有物理删除、批量操作或快照 UI。没有写入正文或更改 CRDT 格式；M2 必须另行验证真实 binary 持久化与恢复。
- 并发 / 性能：同空间元数据写入串行化，列表暂无分页与压测。直接 SQL / 脚本不自动遵守 Service 的授权及锁协议。
- 前端：没有实时成员推送，旧角色可短暂显示但写入仍被服务器拒绝；网络中断可能发生在服务端提交之后，需刷新确认。不承诺撤回已开始的合法读响应。
- 兼容性：本轮验证 Windows Chromium，Linux CI 与 macOS 尚未验证；不新增依赖或浏览器特有业务接口。
- 下一步仅为人工代码审查及后续明确授权的提交 / PR / Linux CI。本轮不开始 M1.5、M2；M1 整体可浏览 OpenAPI 门槛仍未完成。
