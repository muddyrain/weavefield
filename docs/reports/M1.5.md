## 3. 访问方式与契约边界

`ENABLE_OPENAPI_DOCS=1 pnpm dev:api`，或手动在已忽略的 apps/api/.env 设置该值后重启。默认不开启；仅允许 NODE_ENV 未设置、development 或 test，production 和未知模式强制关闭。

- [GET /api-docs](http://127.0.0.1:3001/api-docs)：Swagger UI，只浏览，禁用 Try it out、授权持久化和外部在线 validator。
- [GET /openapi.json](http://127.0.0.1:3001/openapi.json)：OpenAPI 3.0 JSON。

关闭时 UI / JSON / 静态资源均 404，没有遗留默认 JSON / YAML 别名。端口随既有 PORT 配置。main.ts 继续绑定 127.0.0.1；不提供公网或生产 Swagger。

认证使用 HttpOnly Cookie Session，开发名 weavefield_session。七天绝对有效，登录轮换前一个 Cookie 对应 Session，退出删除当前 Session；生产仍使用 Secure __Host- Cookie，但不启用文档。写请求必须有精确 WEB_ORIGIN、application/json 和 X-Weavefield-Request: 1，拒绝 Sec-Fetch-Site: cross-site。JSON 最大 4 KiB；普通字段白名单不变。logout 允许无 body，并忽略合法 JSON 对象/数组；成员移除、文档归档必须提交空对象。

名称 / 昵称 / 标题限制针对 trim 后的 Unicode 字符数，分别 80 / 50 / 200。文档用 pattern 表达 trim 语义，不能用原始字符串 maxLength 错误拒绝合法输入。空间名称 / 标题在 trim 前拒绝控制字符，昵称在 trim 后检查。邮箱原始输入最多 254 个 UTF-16 单元，trim/lowercase 后使用现有宽松邮箱正则，没有虚构更严格的 format: email。密码 12–128 个 Unicode 字符且 UTF-8 最多 256 字节，只出现在必要的请求 Schema，writeOnly，不提供密码响应或真实凭据示例。

## 4. API 清单

以下路径为 API 直连路径，Vite 的 /api 是既有开发代理前缀。W 代表 /workspaces/{workspaceId}，D 代表 W/documents。所有受保护操作需要有效 Cookie。

| Method / 路径 | 成功 | 响应 / 权限 |
|---|---|---|
| POST /auth/register | 201 | AuthSession；注册并建立 Session |
| POST /auth/login | 200 | AuthSession；验证密码并轮换 Session |
| GET /auth/me | 200 | AuthSession；有效 Session |
| POST /auth/logout | 204 | 无响应体；幂等，不要求有效 Session |
| POST /workspaces | 201 | Workspace；任意已认证用户成为新空间 OWNER |
| GET /workspaces | 200 | Workspace[]；仅当前用户加入的空间 |
| GET W | 200 | Workspace；成员可读 |
| PATCH W | 200 | Workspace；OWNER |
| GET W/members | 200 | Member[]；成员可读 |
| POST W/members | 201 | Member；OWNER，按邮箱添加已注册账号，默认 VIEWER |
| PATCH W/members/{userId} | 200 | Member；OWNER，最后 OWNER 保护 |
| DELETE W/members/{userId} | 204 | 无响应体；OWNER，最后 OWNER 保护 |
| GET D | 200 | Document[]；成员，仅未归档，updatedAt 降序 / id 升序 |
| POST D | 201 | Document；OWNER / EDITOR |
| GET D/{documentId} | 200 | Document；成员，匹配空间且未归档 |
| PATCH D/{documentId} | 200 | Document；OWNER / EDITOR，匹配空间且未归档 |
| POST D/{documentId}/archive | 200 | Document；OWNER / EDITOR，含归档时间；不删除快照 |
| GET /health | 200 | Health；公开静态进程探针，不代表数据库 / 正式协作可用 |

安全响应：User 仅 id/email/displayName；AuthSession 仅 user/sessionExpiresAt；Workspace 仅 id/name/slug/createdAt/当前 role；Member 仅 user/role/createdAt；Document 仅 id/workspaceId/title/createdAt/updatedAt/archivedAt。没有 token、tokenHash、passwordHash、ydocRoomName 或 binaryState。

## 5. 权限矩阵与已有覆盖

| 操作 / 条件 | OWNER | EDITOR | VIEWER | 非成员 / 无 Session |
|---|---|---|---|---|
| 空间详情、成员列表、文档列表 / 详情 | 允许 | 允许 | 允许 | 非成员 404；无效 Session 401 |
| 重命名空间、添加 / 修改 / 移除成员 | 允许 | 403 | 403 | 非成员 404；无效 Session 401 |
| 创建 / 重命名 / 归档有效文档 | 允许 | 允许 | 403 | 非成员 404；无效 Session 401 |
| 最后 OWNER 移除 / 降级 | 409 | 无管理权限 | 无管理权限 | 先检查身份与空间权限 |
| 错空间文档、已归档详情 / 改名 / 重复归档 | 404 | 404 | 404 | 有效非成员统一 404；无效 Session 401 |

写请求均先经过解析器与来源校验；矩阵描述通过基本格式检查后的授权结果。401 / 403 / 404 不是固定的全局优先级：

1. JSON 解析最先执行：无效 400、超过 4 KiB 为 413，可先于未登录错误。
2. Workspace / Document：有效 JSON → SessionGuard 身份 401 → 写来源 403 → Controller 参数 / 字段 400 → 事务中的空间成员 404 → 业务权限 / 资源检查。
3. Workspace 管理：验证操作者 OWNER 后才处理目标账号 / 成员及最后 OWNER；普通成员即使引用不存在的目标，也先因无管理权限而 403。
4. Document 创建：空间成员后判断可写角色。改名 / 归档：空间成员后先查有效文档 404，再查写角色 403。VIEWER 修改有效文档 403，修改不存在 / 已归档文档 404。
5. Auth 写路由：解析器 → 来源 403 → 输入 400 → 限流 429 → 业务（例如错误登录 401、重复注册 409、暂时不可用 503）。logout 无输入字段验证和 Session 必须存在的要求。

原测试审计后复用，不为增加数量复制：

- auth.integration.cjs **12 项**：真实 Cookie / 安全 DTO、未知 / 伪造 / 过期 / revoked Session、登录轮换、退出、API 生命周期重启、身份隔离、JSON / CSRF / 输入、旧用户、删除级联、密码计算 503 与限流 429、生产 Cookie。
- workspaces.integration.cjs **10 项**：原子创建、会话隔离、角色矩阵、安全 DTO、非成员同形 404、跨空间成员引用、输入与默认角色、最后 OWNER、自降级 / 退出、并发双降级 / 双退出、等待期间撤权。
- documents.integration.cjs **17 项**：五路由未登录拒绝、OWNER / EDITOR 写入、VIEWER 只读、跨空间 / ID 不匹配、Unicode 标题与未知字段、软归档及快照保留、唯一冲突与新事务重试、改名 / 归档双顺序并发、成员降级后锁后重授权、过期及退出拒绝。

审计没有发现需修改业务语义的新权限缺陷。新增契约用例补齐多个校验层同时失败时的 HTTP 顺序与文档一致性；继续依赖原事务并发用例验证父行锁，没有把 Schema 校验当作授权测试。

## 8. 设计取舍、风险与 M2 前置条件

M1 采用数据库 Session，便于即时撤销与绝对过期，代价是认证查询；Workspace 父行锁让成员变更与文档写入遵循同一撤权协议，代价是同空间写入串行化；Document 软归档保留身份及二进制快照；单一 Prisma 生成任务排除同轮 Turbo 类型检查中的双生成者。上述取舍沿用既有 ADR / PR，不在本轮改造。

- 安全：本轮实测未发现新的权限越界或响应泄密。既有限制仍包括单实例内存限流、无邮箱验证 / 密码找回、无过期 Session 清理和生产部署审查；localhost M0 演示静态令牌不得公网使用。
- 契约维护：文档声明与手写校验是两个维护点，未来新增字段或路由必须同步检查。标准 OpenAPI 字符长度不能完整表达 UTF-8 字节与 UTF-16 单元限制，已明确描述并用真实 HTTP 检查；不能只依赖客户端 Schema 验证授权或输入。
- 并发与数据：直接 SQL、未来 User 删除级联仍可能绕过父行锁协议；同一目录被外部独立命令同时 generate 仍有风险。RepeatableRead 已开始的合法读取可在撤权后完成，后续请求重新授权。
- 兼容与性能：NestJS 11 / Node 22.23.3 在两环境通过；未测 x64 / Windows 本轮修改。只在启用时扫描文档，无每请求生成，没有新增业务查询；未进行独立性能基准。
