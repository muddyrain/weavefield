## 诊断与结论

### P0-A：已复现点击等待失败，修复初始请求与过期夹具的竞态

原 CI 只在 `finally` 的 `context.close()` 处报出 `browserContext.close: Test ended`。远程 artifact 只有 caret 数值，没有 Session Trace，不能从原栈反推清理就是最初卡点。

初次 macOS 原始 main / PR 的单条及完整 E2E 均通过。继续在相同 Linux 环境对照时，原版 PR 实际出现 35 通过、3 失败、1 未运行：文档 Session 场景先失败，Workspace Session 场景随后失败，再引发注册 429。具名阶段将等待定位在 `refresh-expired-document-list` 和 `refresh-expired-workspace` 的 Locator 点击，分别约 15011 ms、15009 ms；context 清理分别仅约 50 ms、40 ms。15 秒阶段预算让失败提前暴露，没有修改原全局 60 秒预算。

根因是测试尚未等初始子请求完成就修改数据库过期时间。Workspace 的 selectSpace 只等待角色出现，此时 DocumentsPanel 已挂载但初始文档列表请求还可能在途。文档 open helper 更先对尚未存在的 panel 执行“loading 数量为 0”的负向断言，这会在空 Locator 上提前成功，再等待面板出现时就不再检查加载完成。

过早过期会使这条初始请求收到 401；应用正确清理身份并卸载受保护弹窗。随后测试却尝试点击已被卸载的刷新按钮，持续等待到超时。文档失败诊断实测列表返回 401、authenticated=false、workspaceOpen=false、pendingHttp 为空，说明业务状态已经清理，阻塞的是测试动作。

为区分其他可能（空间详情/成员请求、聚焦或定时重验、CSS 可点击性），使用真实 HTTP 请求闸门独立验证：拦住初始文档请求 → selectSpace 已返回 → 过期数据库 Session → 释放请求 → 初始列表 401 → 身份和弹窗已消失 → 原刷新按钮点击在 1000 ms 超时。该探针稳定复现同一机制，失败如实保留；没有 mock Session 或改变鉴权。

最小修正：

- Workspace selectSpace 先确认子文档面板存在，再等待初始 loading 消失，确保过期夹具操作晚于初始请求完成。
- 文档 open helper 改为先等 panel 存在，再检查 loading；Session 场景重新打开 OWNER 空间时，另正向确认已显示已知私有文档后才过期。
- 保留真实刷新点击、401、受保护状态清理、本地选择清理、重新登录和退出全部断言；没有接受“自动清理就跳过点击”、force click、sleep 或扩大 timeout。

Workspace 新增 13 个具名阶段及白名单 HTTP 状态（含文档、成员、详情），覆盖从登录到 context 关闭。每阶段最多 15 秒，全局 60 秒不变；失败时保留首个业务错误，清理阶段单独记录。关闭该文件的原始 Trace，仅保留安全 JSON 与日志，不输出账号、密码、Cookie、请求体或 URL ID。

这是有真实 HTTP 证据支持的测试竞态修复，与原 CI 的“超时后 Worker 重启及 429”模式相符。但旧 CI 缺少对应阶段数据，不能声称已证明其唯一历史原因；仍以新 head CI 作为最终门槛。

### P0-C：作者撤销失败是既有问题，不是远端撤销语义误判

先核对 [Yjs UndoManager 官方文档](https://docs.yjs.dev/api/undo-manager)及锁定依赖源码：UndoManager 按 origin 选择追踪；本地撤销不应自动回滚另一作者的独立操作。另用两个真实 Y.Doc 验证：撤销 A 的 tracked-origin 操作后，B 的远端更改保留，语义探针通过。

分别在干净 main 与 PR #7 启动完整应用及独立临时协作服务，在 375×844 双窗口执行相同操作：A 输入初始内容 → B 接收 → 用 Tiptap 命令定位段尾并校验 DOM/模型 Selection → **B 自己键入追加文本** → 双方精确同步及光标验证 → **B 撤销自己的输入**。

两边均失败：B 有输入焦点，自己的事务 `local=true`、origin 为 `y-sync$`、`tracked=true`、`addToHistory=true`、作用于 UndoManager scope，但 undo/redo 栈为空，撤销后内容未变。远端 HocuspocusProvider origin 为 untracked，符合预期。观察到 trackedOrigins 中没有 UndoManager 自身；锁定 Yjs 源码的 destroy 会移除自身 origin 及 transaction 监听，这提示需继续排查编辑器生命周期，但本轮未确认具体调用链。

因此分类为 **main 已存在的本地编辑撤销缺陷**，而不是 PR #7 新回归，也不是“应撤销其他用户修改”的错误期望。本轮保留失败证据，不修改 BlockNote/Yjs 生命周期，不把该探针计入原有 39 项并宣称通过。后续应单独处理作者撤销与重做，保留远端操作隔离。
