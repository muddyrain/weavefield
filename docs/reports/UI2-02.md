### 数据、权限与时序

- 继续使用 `credentials: include`、`cache: no-store`；所有写请求保留 JSON 和 `X-Weavefield-Request: 1`，没有 Token/角色缓存或客户端授权替代。
- Workspace 仍按 `userId` 隔离控制器，Documents 按 `userId:workspaceId:role` 隔离；保留 `alive`、请求 revision 和选中 ID 保护。空间刷新先清 detail/members 并卸载文档控制器；账号/会话变化立即卸载受保护页面，旧响应不能回填新账号。
- localStorage 仅保存 `weavefield.workspace.<userId>` 下的 workspace ID；退出/换账号清旧选择。无历史有效选择时按真实 API 列表选择首项；已失效的历史 ID 不静默替换成其他空间。
- OWNER 管空间和成员、OWNER/EDITOR 写元数据、VIEWER 只读；后端继续最终决定权限。401 清 Session，403 隐藏失效写入口，空间 404 清选择，单文档 404 刷新其有权列表；不把失败当空列表。
- POST/PATCH 真正成功后才显示已提交状态。若随后 GET 503，表单明确“服务端已完成创建，请返回列表并刷新”，阻止重复提交，保留错误。归档收到真实成功响应就从活跃列表移除，即使后续 GET 失败也不把该文档重新显示为活跃。
- 移除成员和归档使用确认 Dialog；取消不写入。最后 OWNER 的真实 409 在确认流程内保持可见，成员身份保持不变。只添加已注册账号，不声称发送邀请。
- 子 Tab 复用同一控制器，未留下新旧两套管理状态。AuthPanel 内部登录表单保留原实现，本轮没有扩大到 UI2-03。
